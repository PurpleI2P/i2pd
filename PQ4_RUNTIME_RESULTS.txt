Investigation + retest (root cause and correction)
- Root cause of previous false-negative checks:
  - I was querying `http://127.0.0.1:<port>/transports` (main page), not the actual transports page.
  - Correct endpoint is: `http://127.0.0.1:<port>/?page=transports`.

- After correcting endpoint:
  - OpenSSL run immediately showed active PQ transport sessions:
    - `pq=4` markers present (example count snapshot: 12, later 30).
  - LibreSSL run still showed no `pq=` markers in `/?page=transports`.

- Additional restart test (LibreSSL):
  - Restarted LibreSSL daemon and forced CLI overrides:
    - `--ntcp2.version=4 --ssu2.version=4`
  - Generated another aggressive wave (HTTP 200 responses and ~12 MB transferred).
  - Result remained:
    - `RESTART_LIBRESSL_PQ4_HITS=0`
    - `RESTART_LIBRESSL_NOW_PQ4_COUNT=0`

- Evidence suggesting why LibreSSL still does not show PQ sessions:
  - Much higher NTCP2 handshake instability on LibreSSL path during stress:
    - frequent `NTCP2: SessionCreated read error: End of file/Connection reset by peer/Operation canceled`.
  - OpenSSL path under the same corrected observation method does establish PQ (`pq=4`) sessions.

Interim conclusion
- PQ transport operation is proven in this environment for OpenSSL build.
- For LibreSSL build, runtime interoperability appears to degrade during NTCP2 PQ negotiation in live network conditions; despite successful PQ unit tests and heavy traffic, no established `pq=4` sessions were observed in webconsole.

Fix + pass #4 (LibreSSL PQ interop restored)
- Root cause fixed in code:
  - `libi2pd/PostQuantum.cpp` used `GetMLKEMIndex()` to pick Noise protocol init constants.
  - Under LibreSSL, `GetMLKEMIndex(mlkem768)` returns 0 (because LibreSSL API exposes only 768/1024), but Noise arrays are indexed as 512/768/1024.
  - This mis-selected ML-KEM-512 Noise constants when ML-KEM-768 was negotiated, breaking live interop.
  - Fix: introduce a dedicated Noise index mapping by crypto type:
    - 512 -> 0, 768 -> 1, 1024 -> 2
    - use this mapping in `InitNoiseIKStateMLKEM`, `InitNoiseXKStateMLKEM`, and `InitNoiseXKStateMLKEM1`.

- Runtime retest after patch (fresh LibreSSL daemon, same environment):
  - Aggressive fanout traffic (4 rounds, high concurrency via local proxy 127.0.0.1:24445).
  - WebConsole checked at the correct endpoint: `http://127.0.0.1:27071/?page=transports`.
  - Result:
